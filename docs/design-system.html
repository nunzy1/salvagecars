SalvageCars.com Design System

Internal Design Document

Status: Draft   |   Version: 0.2

1. Purpose

This document defines the visual and interaction standards used throughout SalvageCars.com.

Its purpose is to create an experience that is clear, consistent, trustworthy, accessible, easy to scan, easy to navigate, and useful across devices.

The design system supports the product architecture and the user journeys defined elsewhere in the project documentation. It does not redefine the site's information architecture, navigation model, content strategy, or repository structure.

The design system should remain intentionally lightweight. New visual patterns and components should be introduced when they solve a recurring user, content, or interaction need.

2. Document Boundaries

To avoid duplication across internal project documentation, each document has a distinct responsibility.

  • Product Architecture defines the major product concepts, capabilities, and how the platform can evolve.
  • Site Structure & User Navigation defines information organization, Jobs To Be Done (JTBD), user journeys, navigation, internal linking, and how visitors move through the site.
  • Repository Architecture defines where source files and internal documentation belong in the repository.
  • Design System defines how information and interactions are presented visually and behaviorally.
  • Content Standards, when created, will define how SalvageCars.com content is written, including voice, terminology, editorial conventions, and writing guidance.

When another project document already owns a concept, this document should reference that concept rather than reproduce it.

3. Design Principles

3.1 Clarity Over Decoration

SalvageCars.com prioritizes understanding over visual decoration.

Design should help visitors:

  • Understand information.
  • Recognize important information.
  • Find answers.
  • Compare information.
  • Make decisions.
  • Determine what to do next.

Decoration should never compete with content. Pages should rely on typography, whitespace, hierarchy, and organization before decorative effects.

3.2 Design Supports Content

Visual design should make information easier to understand and use.

Content should not be forced into a component simply because that component exists. A page does not require cards, illustrations, icons, or callouts unless they improve comprehension, navigation, or interaction.

3.3 Accessibility Is a Foundation

Accessibility is part of the design process from the beginning. SalvageCars.com should aim to conform to WCAG 2.2 Level AA.

Design and implementation should consider:

  • Sufficient color contrast.
  • Readable font sizes and line spacing.
  • Comfortable line lengths.
  • Keyboard navigation.
  • Visible keyboard focus.
  • Semantic heading structure.
  • Descriptive links and controls.
  • Adequate touch-target sizes.
  • Screen-reader compatibility.
  • Zoom and text resizing.
  • Reduced-motion preferences.
  • Information that does not depend on color alone.

Accessibility requirements should influence component design before implementation rather than being added as a final correction.

3.4 Consistency Builds Trust

Similar information and actions should look and behave similarly throughout the site.

Visitors should be able to learn the site's visual language naturally. For example, official sources, warnings, links, navigation, and other recurring patterns should use predictable treatments.

3.5 Authority Should Be Clear

SalvageCars.com combines plain-language guidance with authoritative external information. The interface should make that distinction clear.

SalvageCars.com guidance may include explanations, summaries, educational material, and decision guidance.

Official information may include state motor vehicle agencies, statutes, regulations, government forms, and other primary sources.

Official-source links should eventually use a consistent visual treatment. The design must never imply that SalvageCars.com is a government agency or that its guidance replaces official requirements.

3.6 Design Supports User Journeys

Jobs To Be Done, user questions, navigation paths, and user journeys are defined in Site Structure & User Navigation.

The design system should make those paths easy to recognize and follow, but they must not depend on a particular visual component. A JTBD path may be presented as a text link, heading, list, card, or another accessible interface pattern without changing the underlying journey.

3.7 Progressive Enhancement

Core information and navigation should remain usable without unnecessary reliance on complex interfaces. Enhancements may improve the experience, but essential information should not depend on them when a simpler accessible approach is practical.

3.8 Mobile Is Not Secondary

Pages should work well on small screens as well as large displays. Content hierarchy must remain understandable when layouts collapse into a single column, and important information should not require horizontal scrolling except where unavoidable for specialized structured content.

4. Visual Foundations

4.1 Overall Visual Direction

The visual character of SalvageCars.com should be:

Clean. Calm. Practical. Authoritative. Approachable.

The site should avoid appearing:

  • Busy.
  • Aggressively commercial.
  • Overly promotional.
  • Automotive-themed for decoration alone.
  • Visually intimidating.
  • Like an auction marketplace when presenting educational information.

Information should have enough visual space to be read and understood comfortably.

4.2 Typography

Typography should optimize readability before visual distinctiveness. The system should use as few typefaces and font weights as practical.

Body text

  • Must be comfortably readable without zooming under normal conditions.
  • Should use generous line spacing.
  • Must maintain sufficient contrast against its background.
  • Should avoid excessively wide lines.
  • Long-form content should generally target approximately 60–75 characters per line.

Headings

Headings should establish hierarchy primarily through size, weight, and spacing rather than color alone. Heading levels should follow the semantic structure of the page.

Emphasis

Bold text should be used selectively. Underlining should generally remain associated with links so that link recognition stays clear.

4.3 Spacing

Whitespace is a functional part of the interface. It should separate unrelated concepts, group related information, improve scanning, and establish hierarchy.

A consistent spacing scale should be used instead of arbitrary values. Related elements should appear visually closer together than unrelated elements.

4.4 Content Width

Long-form content should not stretch across the full width of large screens. Article and guide text should use a comfortable maximum reading width.

Wider layouts may be used where the information requires them, such as navigation, state indexes, structured comparisons, tables, and tool interfaces.

4.5 Color

Color should have a functional purpose. The initial palette should remain restrained and provide colors for primary text, secondary text, page backgrounds, surfaces, borders, links and actions, success, warnings, errors, and informational states.

Meaningful text and controls must meet the appropriate WCAG contrast requirements.

Color must not be the only method used to communicate meaning. A warning, for example, should also be identifiable through text, labeling, structure, or another non-color indicator.

4.6 Borders, Shadows, and Depth

Prefer subtle borders and spacing before shadows when separating content regions. Shadows should be used sparingly and should communicate interface relationships rather than decoration.

4.7 Corners

Corner rounding should be subtle and consistent. The site should feel modern without relying on exaggerated rounding or other short-lived visual trends.

5. Information Hierarchy

This section defines the visual hierarchy of content. Editorial rules for writing headings, paragraphs, terminology, warnings, links, and other content belong in Content Standards.

5.1 Page Hierarchy

Pages should establish a clear visual progression from primary information to supporting information. The page title and main purpose should be immediately recognizable, while secondary details and metadata should remain visually subordinate.

5.2 Page Titles and Headings

Each page should have one visually dominant primary heading. Subsequent heading levels should create an obvious, consistent hierarchy that remains understandable when the page is scanned.

5.3 Body Content

Paragraph spacing, list spacing, text width, and line height should make long-form information comfortable to read and easy to scan. Dense uninterrupted blocks of content should be avoided through appropriate structural hierarchy.

5.4 Emphasized Information

Important information may receive stronger visual treatment when additional attention improves comprehension or safety. Not every useful fact should become a callout; overuse reduces hierarchy and makes pages harder to scan.

5.5 Official Sources

Official sources should have a recognizable and consistent visual treatment that identifies them as authoritative external information without making them compete with the page's primary content.

5.6 Metadata

Metadata such as last-reviewed dates, state labels, content types, or source authorities should remain visually secondary while still being easy to locate when relevant.

5.7 Contextual Next Steps

When a page offers a next step, the interface should make that action easy to identify without turning informational content into a promotional experience. The underlying user journey is defined in Site Structure & User Navigation.

6. Component Independence

Information architecture and user journeys must not depend on a particular visual component.

For example, a path such as I need my state's salvage requirements may initially appear as a simple text link and later be presented as a card containing additional context.

The underlying destination and user journey remain the same. This allows SalvageCars.com to launch useful experiences before every possible component has been developed.

7. Design System Evolution

This document is a living standard and should become the authoritative source for SalvageCars.com visual and interaction decisions.

As decisions are made, this document may be expanded to include exact typography specifications, colors, spacing values, content widths, responsive breakpoints, Tailwind implementation conventions, links, buttons, callouts, tables, forms, navigation patterns, and reusable components such as cards.

Components should be added when recurring needs emerge from real content and user journeys.

Need → Pattern → Standardize → Reuse

Clarity over decoration. Consistency builds trust. Design helps visitors understand their situation and know what to do next.
